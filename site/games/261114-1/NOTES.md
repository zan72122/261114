# じゅわっ！ママとおなじぎょうざづくり (gf-261114-nx1)

- **起動**: `index.html` を開くだけ（1ファイル・オフライン・file:// と Pages サブフォルダの両対応）。作り直しは `node build.mjs`（`src/*.js` と `vendor/three.min.js` を `template.html` に埋め込む）。開発用に `#wrap` `#fry` `#eat` で場面から始められる。
- **お話**: つつむ（あん→ふちに水→たたむ→ひだ ×3個、ママのとなりへ「こてん」）→ やく（ならべる→火→水で「じゅわっ」→ふた→ひだの位置から羽根が伸びる→火を消す→皿をかぶせてひっくり返す）→ たべる（パリッと取り分け、たれ、ぱくっ、ママにおすそわけ）→ 夕方のやさしい終わり → 大皿タップでもう一度。
- **確認したこと**: 390×844 で最初からおしまい・やり直しまで1回通し、コンソールエラー 0。各段階で次に触る物が光（スポット＋光の輪）で1つだけ示されること、放置時の半透明の指のお手本、ひだの数で羽根の伸び方が変わることを画面で確認。
- **未確認**: 実機（iPhone/iPad）の速さ・音の聞こえ方・タッチの感触、横持ち、非表示からの復帰。確認環境はソフトウェア描画で遅く、テンポは目で見られていない。
- **既知の問題**: 羽根の「ひだによる違い」は伸びる途中がいちばん分かりやすく、焼き上がりでは控えめ。縦持ちでは、ふた・大皿の置き場所が画面右端に少しかかる。取り皿より羽根のかけらが少し大きい。画像生成サービスは使えなかったため、テクスチャは全部 Canvas の手続き生成。
- **描画の負荷対策**（iPhone/iPad むけ、見た目と遊びは同じ）: 影マップは影を落とす物・光が変わったフレームだけ描き直す（カメラだけの移動では描き直さない。夕方へ移る間の太陽の動きは4フレームに1回）。解像度は「画素数 ≦ 約280万」の段から始め、60fps 近くが6秒続けば1段上げ、約48fps を割る状態が1.2秒続けば1段下げる（上げてすぐ重くなった段には戻らない）。起動直後にほかの場面の道具のシェーダーも先にコンパイルし、場面が変わる瞬間の引っかかりを防ぐ。safe-area の読み取りは毎フレームから約0.5秒ごと＋画面の大きさが変わった時に。
- **初回起動の速さ**（見た目と遊びは同じ）: 手続きテクスチャは起動中は縦横 1/2〜1/4 の粗い版（または平らな法線・平均色の仮版）ですぐ出し、本番の解像度は明転が終わってから1フレーム5ms（重い端末は最大8ms）ずつ裏で描いて同じ Canvas に書き戻す（`G.util.bg`。差し替え後の画素は元と完全に同じ）。高さ→法線は作った時の画素を手元に残して使い、遅い GPU からの読み戻し（getImageData）を避ける。裏の仕事が動いている間は適応解像度の計測を止める。ほかの場面のシェーダーの先読みは使える端末では並列コンパイル（compileAsync）。確認環境（ソフトウェア描画）では起動処理が約4.0秒→約1.2秒。
