# カタカタ！ミシンでつくるおでかけバッグ（261114-3）

識別子: gf-261114-nx3

## 起動方法
- `index.html` をそのまま開く（file:// でも Pages のサブフォルダでも可）。1ファイル完結・オフライン・外部読み込みなし。
- 作り直すとき: `npm install` → `node build.mjs`（`src/` と three.js を `index.html` に埋め込む開発時ビルド。実行時ビルドは不要）。

## お話と操作（指1本）
布を半分に折る → りんごを入れて持ち手を持ち上げると、あいた横からころん → ミシンで片側を縫う（布を針のほうへ押す）→ こんどは反対側からころん → もう片側も縫う → 落ちない＝バッグ完成 → ボタンをつけ、すいとう・おべんとう・ハンカチを入れる → 持ち上げて公園へ → 中身を出してピクニック → おうちの壁に完成バッグが並び、次の柄の布が出る。

発見: 折ると柄が表に出る／縫い目は指のぶれどおりに残る／糸巻きをさわると糸の色が変わる／はずみ車で1針／缶からボタンが出てくる／柄は4種類が順に出て、完成品は壁に3つまで残る。

## 確認したこと
- 390×844 で読み込み・開始時にコンソールエラーなし。お話を最初から次の周の始まりまで1回通し、各段階で「次の1操作」が画面内の合図（光・ゆれ・光の輪、放置で指のお手本）で示されることを画面で確認。
- 自動操作のブラウザ（ソフトウェア描画）での確認のみ。実機（iPhone / iPad）と音の聞こえ方は未確認。

## 既知の問題
- 持ち上げてりんごが転がる演出（約2.5秒）の途中で指を離すと、演出が終わるまでバッグが宙に残る。
- 缶から追加で出したボタンは、バッグに付ける前に再読み込みすると消える（付けたボタンは残る）。
- 縦持ちの電話では机全体が小さめに映る。縫う場面と持ち上げる場面は寄る。
- 横向きは一部の場面しか見ていない。
- 木目・布・背景はすべてコード内の手続き生成（外部素材・外部AIなし）。

## 描画の軽量化（iPhone / iPad 向け）
- 影マップは毎フレームではなく、影を落とす物・形・光が変わったフレームだけ描き直す（`engine.js` の影の比較）。止まっている場面では影の描画パスを丸ごと省く。
- 描画ピクセル数に上限（約300万px）。電話は従来どおり2倍解像度、iPad など大画面だけ解像度を少し下げる。
- 自動画質調整の目標を 60fps に変更。下げても速くならないとき（省電力モードの 30fps 固定など）は元に戻して打ち止め。
- 布・持ち手・縫い目は、形が変わったときだけ GPU に送り直す。毎フレームの配列生成も削減。
- 公園にも明るさ0のスポットライトを置いて部屋と光の構成を揃え、部屋を見せたまま公園のシェーダーも先に作れるようにしている（公園へ切り替える瞬間の止まりを解消）。
- 見た目と遊びは変えていない（自動操作ブラウザでの比較のみ。実機での fps は未計測）。

## 初回起動の高速化
- 縦長の画面で最初の場面から始まるとき（初めて遊ぶ人など）は、最初の場面の1枚絵（`assets/fallback.jpg`、約22KB）をすぐ出す。3D の最初の1コマが描けたら 0.45 秒でふわっと消して入れ替える。横長や途中から再開するときは出さない。
- 本体スクリプトは `<script type="text/plain">` に入れておき、1枚絵が画面に出てから実行する（大きなスクリプトの実行で最初の表示が止まらないように）。
- 公園（芝・背景・シート・草・落ち葉・木漏れ日）は起動時には作らない。遊び始めて約1.2秒後から、指で動かしていないときに1部品ずつ作り、続けて絵を GPU へ送り、シェーダーを `compileAsync` で作っておく（`world.preparePark` / `game.js` の `warmPark`）。公園の場面から再開したときや間に合わなかったときは、`world.show('park')` がその場で仕上げる。
- 起動時に作るシェーダーは 29 → 23 個。自動操作ブラウザ（ソフトウェア描画）で、最初の表示は約5.5秒 → 約0.05秒（1枚絵）、3D の最初の1コマは約0.5秒早くなった。実機では未計測。
